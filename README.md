# T20 Oracle

Predict the winner of a T20 cricket match with machine learning, trained on 12,000+ historical games.

The models use features such as teams, venue, toss and recent performance. A small FastAPI backend serves predictions (`backend/`), and the training notebooks are in `Notebooks/`.

## What's done

- Trained and compared Logistic Regression, Random Forest and XGBoost
- Hyperparameter tuning with GridSearchCV
- Evaluated with accuracy, log loss and Brier score
- FastAPI service around the trained model

## Results and limitations

Trained and evaluated on 12,559 T20 matches from [Cricsheet](https://cricsheet.org/) (T20 internationals plus major franchise leagues, downloaded November 2026). Evaluation is on a chronological holdout: the models train on the oldest 80% of matches and are tested on the most recent 20% (2,442 matches, May 2025 to November 2026), with all preprocessing fit on the training set only.

| Model | Accuracy | Log loss | Brier score |
| --- | --- | --- | --- |
| Logistic Regression | 0.673 | 0.608 | 0.210 |
| Random Forest | 0.677 | 0.619 | 0.215 |
| XGBoost | 0.684 | 0.603 | 0.208 |

An earlier version of this README reported ~73% accuracy (log loss 0.54, Brier 0.18). Those numbers were inflated by data leakage and have been corrected:

- **Form features included the match being predicted.** Player stats (runs, wickets and Player of the Match) were folded into the "recent form" features *before* those features were computed for the match, so the model effectively saw how the match went before predicting it. Fixing this alone drops accuracy from ~74% to ~60-62% under the original random split.
- **Matches were processed in arbitrary file order**, so "recent" history could include future matches. They are now processed in date order.
- **Random train/test split** replaced with a chronological one, and the label encoders and scaler are now fit on the training set only.
- No-result matches (no winner to predict) are skipped instead of being labelled as losses.

Under the original random-split protocol but with the leakage fixed, accuracy is ~62%; the chronological holdout above (~67-68%) reflects realistic "predict the next matches" performance, since recent matches have fully informed history features.

Known limitation: the FastAPI service fills most numeric features with hard-coded averages at inference time, so served predictions are driven by teams, venue and toss rather than live form data. The saved artifacts in `backend/models/` should be regenerated by running `Notebooks/train.ipynb` after pulling this change.
